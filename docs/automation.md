# 自動化方針と実装の対応（2026-09-08, ユーザー提示の「完全自動」方針）

> 目的: 「自動で整える」と「元に戻す」を主要操作にし、利用者の判断は**業務ルールの変更が要るときだけ**に限る。
> ここは方針の各項目が現行実装のどこに当たるか（済／部分／未）を固定する表。未の項目は `docs/backlog.md` #13。

## 1. 自動化の範囲

| 処理 | 方針 | 現状 |
|---|---|---|
| 勤務表セルの変更・交換・研磨・LNS・再構築 | 完全自動 | **済**（`V6FinalPort.optimize` → `runPostOptimization` の後処理チェーン。すべて keep-best） |
| アルゴリズム選択 | 完全自動 | **済**（`V6Algorithm.AUTO`＝時間予算で RSI/ALNS 等を選ぶ。明示選択も可） |
| 時間予算・並列数 | 完全自動 | **部分**（並列数は `availableProcessors` 既定。時間予算は利用者設定＝問題規模からの自動計算は未） |
| 候補比較・最良案選択 | 完全自動 | **済**（`betterReport`＝hard→weightedScore→total の辞書式。同順位は生成順） |
| 適用後の完全評価 | 完全自動 | **済**（`UnifiedViolationChecker` が source of truth。最終番兵は入力比で退化を拒否。改善提案も 3.509.4 から適用直前に `FixApplyGate` で仮盤面を完全再評価し、辞書式で改善しない・希望固定/回数固定を崩す提案は反映しない） |
| 保存・履歴・Undo | 完全自動 | **済**（自動保存、`pushUndo` は最適化開始時に 1 回＝1 タップで開始前へ） |
| 個人上下限・必要人数・希望固定・禁止連・担当可の変更 | 自動変更しない | **済**（最適化器は設定を一切変えない。提案は Sanity／「なおすのを手伝って」が出すだけ） |
| 制約緩和 | 利用者承認 | **済**（`SettingFixAction` はワンタップ承認式） |

## 2. 探索の段階（小さい変更から拡大）

| 段階 | 方針 | 現状（後処理チェーンの対応パス） |
|---|---|---|
| 1 セル再配置 | 済 | `C3nPolish`／`RangePolish`／`AptPolish`（単セル＋玉突き連鎖 `findCovUChain`） |
| 同日 2 職員交換 | 済 | `CyclicSwapPolish`（k=2,3）／`C1同日交換` |
| 同一職員 2 日交換・同長区間交換 | 済 | `C3Sequence`（2〜3 日）／`AnchoredWindowSwap`／`AdaptiveBlockSwap`（11〜28 日） |
| 3〜5 職員循環交換 | 部分 | `BlockRotation`（3 者）／`ChainSwap3/4`（RSI 後期）。5 人は未 |
| 違反連結成分修復 | 済 | `ViolationComponentRepair`（巡の末尾＋最終段） |
| 小〜大規模 LNS | 済 | `C1JointLns`／`PersonalBalanceJointLns`／ALNS（destroy-repair） |
| 停滞時の自動拡大 | **未** | 現状は「1 巡で採用 0 なら終了」。段階的な半径拡張は backlog #12(b)・#13 |
| 実現不能診断 | 済 | `V6SanityPort`（forcedCovU・6b/6c・配布不可）＝設定変更案だけを提示 |

## 3. 候補の自動選択と適用ゲート

| 方針 | 現状 |
|---|---|
| 必須ゼロ → 必須数 → 必須加重 → ソフト加重 → 希望充足 → 変更職員数 → 変更セル数 → 期間 → 元に近い → 生成順 | **部分**: hard → weightedScore（必須・ソフトの加重を 1 本で）→ total。希望固定は HARD（pref 9000）なので「希望充足」は必須側に含まれる。変更職員数・セル数・期間・元との距離は**採用基準に入れていない**（決定: 採用基準を増やさない＝`CLAUDE.md`）。同順位は生成順で決定的 |
| 必須が増えない／担当外・希望固定・禁止連・個人固定の新規違反なし | **済**（HARD 族は辞書式の先頭。厳密ピン lo==hi は `exactPinRegression` で別途拒否） |
| 「必須減少・ソフト悪化は正規化ソフト損失 5% 以内なら採用」 | **未・決定待ち**: 現行は必須減少なら常に採用（辞書式）。上限を入れるのは採用基準の変更＝HF77 と同じく明示指示で 1 件ずつ |
| 差分評価と完全評価の一致 | **済**（Δ×フル整合、C++ は 2 層番兵。`ObjectiveParityTest`） |
| 再現性（同一入力・seed） | **済**（決定的モード 3.507.3。通常モードは時間予算依存） |
| 失敗時は開始前へ原子的に戻す | **済**（keep-best＝入力より悪い結果は返さない。例外時は前回盤面を維持） |

## 4. 制約族ごとの自動処理（方針表の各行）

covU/covO/groupViol/pref/low/high/apt/C1/C3 系/fair/weekly/希望島 は専用パスあり（`docs/algorithm_portfolio.md`）。
**C2**・**C41/C41s**・**C42/C42s** は汎用交換＋成分修復のみ（専用研磨は backlog #12(b)）。

## 6. UX 評価（2026-09-08 ユーザー提示）への対応

| 優先 | 項目 | 状態 |

| 2 | 1 手候補ゼロから広域修復へ自動接続 | 未（#13(g)。ホームの「AIの解決提案」で候補なしのとき「自動で整える」へ誘導/自動起動） |
